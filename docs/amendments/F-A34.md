# F-A34

**Right-click** (not a pen's barrel: F-A31 opens no menu within 600 ms of a pen pan) opens the palette as a menu at the pointer (`openPicker(prompt, items, {x, y})`: clamped to the window, no scrim, a press outside closes it; it stays the `palette` transient for the keys) with the actions of what is under it: a card, a folder's tab or deck, a row of the folder tree or of a deck (all resolved through `S.nodes`, so ink strokes and shapes, which carry `data-id` too, are never cards) get `actionsFor(n)`, the list `.` shows too (the header buttons that are not hidden by the `hidden` attribute or by the folder's `.hdown`/`.d-fs` state, Pipe, Tag, Arrange, the card commands, and Delete, which takes a second pick as ✕ takes a second click, since nothing brings a removed card back); an edge label its other types and delete; a shape edit text and remove; anything in the selection the selection's commands (selected ink by the box around it, since strokes take no pointer events); the canvas, a folder's inside and the tree's loose row New page, shell, folder, sketch and browser window ("here": the existing creators with a one-shot place, top-left at the pointer and in the folder under it) and Fit.
A shell adds Copy and Paste, an Edwin frame Copy the region and Paste at the click.
A right-click selects its card or folder.
The browser's menu stays for Shift+right-click, for text fields, selects, contenteditable and links outside Edwin frames, and wherever the menu would be empty (the side pane, the other views); inside a terminal whose program tracks the mouse the event is only prevented, so the program has the button.
The menu key and Shift-F10 open it for what has the keys, anchored on it: a terminal or an Edwin frame (the dock's and the Editor view's too), else the selected card on the canvas; a menu key the terminal's program took opens nothing, and does not make the next right-click a keyboard one.
Closing the menu gives the keys back to the terminal or frame that had them, unless the pick moved them.
A pen's barrel button (button 2) opens it instead of inking; a touch long-press (the browser's own `contextmenu`) opens it when the one-finger pan it started has not moved, and ends that pan
