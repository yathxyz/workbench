# F-A37

Keys K4 (§10.9): the board's keymaps are Edwin keymaps when the frame runtime runs.
Before the user's `init.scm`, each `WBKeys.MAPS` keymap becomes an Edwin keymap `wb-NAME-map` (`wb-canvas-map`, `wb-leader-map`, `wb-leader-d-map`, ...) holding a Scheme command `wb-CMD` per board command (`wb-hints`, `wb-desk-new`; the doc string is the which-key label), the leader is a prefix in `global-map` bound to `wb-leader-map` (moved when the leader changes), and the feature `wb-keys` is provided.
A `define-key` in one of these keymaps changes the board's binding, which-key and the palette's key labels at once: a binding to a `wb-` command or keymap is that command or prefix (a prefix keymap made under the leader joins as one of its own), and one to any other Scheme command runs that command in the frame runtime (row `edwin:NAME`; Edwin's `s-` keys cannot be named by `define-key`, so the `s-` rows stay as `web/keys.ts` has them).
The checker runs after each change and reports in the echo area.
`init.scm` also runs in edwind and desktop Edwin, so a rebinding is written `(when (featurep 'wb-keys) (define-key wb-canvas-map "g" 'wb-hints))`.
Without the frame runtime the keys are `web/keys.ts`'s rows, as before
