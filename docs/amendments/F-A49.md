# F-A49

**Session configuration, without a page change** (2026-11-17).
The hub materialises valid full `configOptions` lists in `Summary.acp` and `AcpSessionInfo`, bounded to 64 options and 64 KiB of serialized JSON (§3.2.9).
Malformed configuration results and updates keep the existing offering; oversized legacy journal offerings fold to none.
Malformed setup offerings are omitted without failing setup or revive.
Successful `session/set_config_option` results are journaled as `config`; requests accept epoch-checked select (including grouped choices) and boolean values (§3.2.7, §3.4.5).
A non-empty ordered `SpawnAcp.config` batch runs in the hub after setup, before any client's prompt or other gated live action; the initiating open waits and reports per-entry `configErrors`.
Journal faults release the batch and answer the opener even without an agent process.
The hub advertises support with `acpConfig:true`; the API and `/acp` relay reject non-empty startup config on older hubs.
The relay accepts the ordered array, returns opener errors on `hello` and supports `set_config_option` for a future page, but this amendment adds no page UI.
The mesh API's control scope can configure one session or pass an ordered object of at most 16 string-or-boolean options on creation, translated into the hub batch (§3.8.2).
No create sends a prompt.
