# F-A51

**Session task references** (2026-11-19).
An ACP session or a harness-reported session may name its work with a single free-text `task`, such as an issue URL or a task id.
Reject C0 controls and DEL, trim surrounding whitespace and reject more than 512 UTF-8 bytes after trimming; an empty result means no task.
The control API accepts `task` on `POST /v1/sessions` and accepts a required string or null on `POST /v1/sessions/{sid}/task`, where null also clears it.
The hub accepts `SpawnAcp.task` and `acp.set_task`; the API refuses a non-empty startup task or any task mutation unless that connection's hub hello advertises `acpTask:true`.
An invalid task is `bad_request` at the hub and HTTP 400 at the API, never a partial value.
The hub journals a `task` event on setting or clearing the reference and exposes its current value as `Summary.acp.task`, omitted when unset.
Neither revive nor hub restart changes it, and no reference is sent to the agent or attached to a PTY session.
A harness event's string `task` replaces the observed reference, including clearing it with an empty string; absent or null leaves it alone.
The observed registry persists the value, and rejects invalid reports without changing the session.
An Agents row uses the joined hub session's task when present, otherwise the observed task.
The row ellipsises the reference; a Task line in Details shows its full text.
Only a whole HTTP or HTTPS URL is a link (`target="_blank"`, `rel="noopener noreferrer"`); all other references are plain text.
In the Agents list `g` switches between repository groups (default) and task groups, with roots that have no task together in the last group and descendants still nested under their parents.
Grouping is per viewer in page memory, like the Details disclosure, not shared board state.
